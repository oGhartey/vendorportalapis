Vendor Portal API

Endpoints for the Vendor Portal to check Demo/UAT slot availability, book and cancel sessions on behalf of a delivery partner, review a partner's booking history, and join the waitlist when no slot is open. Every partner must complete a Demo/UAT session and receive an Approved decision from VaMijo before live API credentials are issued.

Base URL https://admin.vamijogh.com/vendorportal Auth Bearer static token Format application/json

01Overview

The Vendor Portal API is a small, purpose-built surface for one job: getting a delivery partner through their Demo/UAT session. It does not expose ride, delivery, or wallet data — only Demo/UAT slots, bookings, and the waitlist. All five endpoints live under a single base path and share one authentication scheme.

Who calls this API: the Vendor Portal backend, on behalf of whichever delivery partner is currently signed in there. This API is not partner-session aware — every request must state which partner it's acting for by passing partner_id explicitly.

02Authentication

Every request must include a static bearer token in the Authorization header. VaMijo issues this token to the Vendor Portal team out of band — it is shared across all requests and is not specific to any one partner, which is why partner_id is a required field on every endpoint below.

Authorization: Bearer <YOUR_API_TOKEN>

Failure response

401missing, malformed, or incorrect token
Invalid or missing API token
This one response is returned as plain text, not the JSON envelope described below — it is rejected by the authentication layer before your request reaches the API itself. Check for it before attempting to parse the body as JSON.

03Errors & response envelope

Every endpoint (aside from the 401 above) responds 200 OK at the HTTP layer and carries the real outcome inside a JSON body. Always check status in the body, not just the HTTP status code.

// success { "status": 200, "message": "...", "info": /* payload */ } // failure { "status": 409, "message": "Slot no longer available" }
Body status Meaning Typical cause
200 Success Request completed as expected
400 Validation error A required field is missing or the wrong type
404 Not found The slot_id or booking id doesn't exist
409 Conflict Slot filled/closed since it was listed, duplicate active booking, already on the waitlist, or a cancel/ownership mismatch
500 Server error Unexpected failure — retry, then contact VaMijo if it persists

04Endpoints

GET/vendorportal/slots Bearer token
List open, bookable Demo/UAT slots. A slot only appears here if it is still OPEN, has spare capacity, and is far enough in the future to be booked (past its booking_cutoff_minutes window).

Query parameters

Field Type Description
startDate ISO date optional Restrict to slots on/after this date. Must be paired with endDate.
endDate ISO date optional Restrict to slots on/before this date. Must be paired with startDate.
page integer optional Page number, 1-indexed. Defaults to 1.
limit integer optional Records per page. Defaults to 10.

Sample request

curl -s "https://admin.vamijogh.com/vendorportal/slots?startDate=2026-10-01&endDate=2026-10-15&page=1&limit=10" \ -H "Authorization: Bearer <YOUR_API_TOKEN>"
200Available slots
{ "status": 200, "message": "Available slots", "info": { "pagination": { "totalRecords": 5, "recordCount": 5, "totalPages": 1, "limit": 10, "currentPage": 1 }, "records": [ { "slot_id": 42, "slot_datetime": "2026-10-06T10:30:00.000Z", "duration_minutes": 30, "mode": "VIRTUAL", "location": null, "capacity": 1, "booked_count": 0, "reviewer_admin_ids": null, "booking_cutoff_minutes": 60, "status": "OPEN", "date_created": "2026-09-21T21:27:13.590Z" } ] } }
An empty records array is not an error — it means nothing is currently bookable. Point the partner at Join waitlist in that case.
POST/vendorportal/bookings Bearer token
Book a partner into a slot returned by GET /slots. Availability is re-checked atomically at booking time, so a slot listed as open a moment ago can still come back 409 if another request filled it first.

Body parameters

Field Type Description
partner_id integer required The delivery partner being booked in.
slot_id integer required The slot to book, from GET /slots.
contact_name string optional Attendee name for this session.
contact_phone string optional Attendee phone number.
contact_email string optional Attendee email.
notes string optional Anything VaMijo's reviewers should know ahead of the session.

Sample request

curl -s -X POST "https://admin.vamijogh.com/vendorportal/bookings" \ -H "Authorization: Bearer <YOUR_API_TOKEN>" \ -H "Content-Type: application/json" \ -d '{ "partner_id": 42, "slot_id": 42, "contact_name": "Jane Mensah", "contact_phone": "+233201234567", "contact_email": "jane.mensah@example.com", "notes": "First integration test session" }'

PATCH/vendorportal/bookings/{id}/cancel Bearer token
Cancel a booking. Frees the slot's capacity and reopens it if it was full. Scoped to partner_id — a partner cannot cancel another partner's booking even by guessing a valid id.

Path parameter

Field Type Description
id integer required The booking_id to cancel.

Body parameters

Field Type Description
partner_id integer required Must match the booking's owning partner.
cancel_reason string optional Free-text reason, stored on the booking.

Sample request

curl -s -X PATCH "https://admin.vamijogh.com/vendorportal/bookings/108/cancel" \ -H "Authorization: Bearer <YOUR_API_TOKEN>" \ -H "Content-Type: application/json" \ -d '{ "partner_id": 42, "cancel_reason": "Reschedule requested by partner" }'

POST/vendorportal/allowed-ips Bearer token
Add an IP address to a partner's allowed_ips whitelist. Appends to the partner's existing list rather than replacing it, and is idempotent — adding an IP that's already whitelisted is a no-op, not an error.

Body parameters

Field Type Description
partner_id integer required The partner whose whitelist to update.
ip string required A single IPv4 or IPv6 address to whitelist.

Sample request

curl -s -X POST "https://admin.vamijogh.com/vendorportal/allowed-ips" \ -H "Authorization: Bearer <YOUR_API_TOKEN>" \ -H "Content-Type: application/json" \ -d '{ "partner_id": 42, "ip": "197.251.20.10" }'
200IP added to whitelist successfully
{ "status": 200, "message": "IP added to whitelist successfully", "info": { "allowed_ips": "197.251.20.10" } }
200the IP was already on the whitelist — not an error
{ "status": 200, "message": "IP is already whitelisted", "info": { "allowed_ips": "197.251.20.10" } }

Failure response

404the partner doesn't exist
{ "status": 404, "message": "Partner not found" }
Adds one IP at a time — it never removes any. Use Remove allowed IP to take one off the list, or contact VaMijo support to fully reset a partner's whitelist.
DELETE/vendorportal/allowed-ips Bearer token
Remove an IP address from a partner's allowed_ips whitelist. Idempotent — removing an IP that isn't on the list is a no-op, not an error. Also stamps the partner's status_reason to "IP address removed".

Body parameters

Field Type Description
partner_id integer required The partner whose whitelist to update.
ip string required A single IPv4 or IPv6 address to remove.

Sample request

curl -s -X DELETE "https://admin.vamijogh.com/vendorportal/allowed-ips" \ -H "Authorization: Bearer <YOUR_API_TOKEN>" \ -H "Content-Type: application/json" \ -d '{ "partner_id": 42, "ip": "197.251.20.10" }'
200IP removed from whitelist successfully
{ "status": 200, "message": "IP removed from whitelist successfully", "info": { "allowed_ips": null } }
200the IP wasn't on the whitelist — not an error
{ "status": 200, "message": "IP was not on the whitelist", "info": { "allowed_ips": null } }

Failure response

404the partner doesn't exist
{ "status": 404, "message": "Partner not found" }
This also updates status_reason. A successful removal sets the partner's status_reason to "IP address removed" — it does not change status itself, only the reason field, so this is visible on the partner's record without blocking their account.

05Booking status values

The booking_status field returned by Create booking and List bookings moves through one of these values over a booking's lifetime:

Status Meaning
SCHEDULED Booked and upcoming.
COMPLETED_PENDING_DECISION The session happened; VaMijo hasn't recorded a UAT decision yet.
APPROVED VaMijo recorded an Approved decision — the partner's integration passed UAT.
REMEDIATION_REQUIRED Issues were found; the partner needs to fix and rebook.
FAILED The integration did not pass UAT.
CANCELLED Cancelled by the partner or VaMijo before it took place.
NO_SHOW The partner did not attend.
Live API credentials are gated on this status, not on booking existence alone: only an APPROVED decision unlocks a partner's live api_key/api_secret. A completed session with no decision yet, or any outcome other than Approved, means the partner is still blocked from going live.

06Waitlist status values

The status field returned by List waitlist requests moves through one of these values:

Status Meaning
WAITING Default on join — no slot fit at the time. A partner can only have one WAITING request at a time; joining again while one is already WAITING returns 409 (see Join waitlist).
INVITED VaMijo has notified the partner that a slot opened up.
BOOKED Resolved into an actual Demo/UAT booking.
CANCELLED Withdrawn without a booking — either by the partner via Cancel waitlist request or by VaMijo.
Only a WAITING request can change state. Once a request is INVITED, BOOKED, or CANCELLED it's resolved for good — cancelling it again returns 409.

For a token, a change to allowed_ips, or anything behaving unexpectedly, contact the VaMijo integration team through your existing onboarding channel.
